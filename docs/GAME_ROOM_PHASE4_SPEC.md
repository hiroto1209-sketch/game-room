### 0. 一文で表現する完成体験

「パーティールームの扉を開くと、池・森・ブロック遺跡が広がる夜の世界へシームレスにつながる。友達3人で散策し、中央の照準で不思議な物体を動かし、専用アリーナでエネルギーブラスター対戦を楽しみ、部屋へ帰るとお知らせ看板とゲーム筐体から新しい遊びに挑戦できる。」

**世界の核:** 離れている友達が、同じ場所にいて、同じものを見て、同じ変化を起こせること。

**3つのWOW体験:**
1. **THE DOOR** — いまあるパーティールームの右壁に出口が生まれ、屋外へ本当に徒歩で出られる。読み込み画面を挟まない。戻れる。
2. **TRI-LINK POND** — 夜の池に3つの光る結晶。3人がそれぞれ照準を合わせて3秒間維持すると池上に光の橋が浮かぶ。1人の場合は単独で順にスイッチを起動できる。橋はルーム全員に同期する。
3. **GLITCH ARCADE** — 左のARCADE端末を起動すると、空中に浮くブロック床の専用ゲーム空間へ切り替わり、色の合う床を選ぶラウンドが始まる。派手だが低負荷・非グロテスクな演出で全員が同じ勝敗を見る。

**初期の地形運用範囲:** おおむね x=-32〜128、z=-64〜64 の約160×128単位。これは設計上のテスト領域でありFPS保証ではない。地形は決定論的な`worldSeed`で生成し、ネットワークで全草・全木の座標を送り続けない。

**出口を作る際の絶対条件:**
- `PartyWorld.js` にある右側の連続壁 `cube(10,2,-4,.3,4.1,24.4,wall,true)` を、ドア部分だけ空けた**2つの壁セグメント**へ置換する。壁面の見た目だけ穴にしても、古いAABBの当たり判定を残してはならない。
- 壁の装飾線もドア部分には表示しない。モニター x=9.6,z=4.1 と右奥家具を移動・破壊しない。
- 屋外と屋内の地面高さをつなげる。段差を設ける場合はPlayerControllerに明示的な地面高さ／ステップアップ判定を加える。
- 夜の室内と屋外の色調をつなぐ。外を開けても遠景が黒い空白やクリッピングにならない。
- 開いた扉は**飾りではなく、本当に往復できる経路**であること。

### 4. 技術規約・ワールドと通信の同期

- **WorldStateは二種類に分離:**
  - `persistent`: worldSeed、現在の共有モニター写真、照明、看板文言、ホストが保存した編集可能な家具配置。
  - `ephemeral`: 接続プレイヤー、HP、弾数、マッチの残り時間、標的、倒された状態、操作中の物体。
- **room versioning:** `worldStateVersion:2` と `revision` を定義。古い`shared_room_v1`は読み取り互換で残す。7日間で写真が消える既存方針は、今後の永続ワールド全体削除と同一にしない。写真だけTTL管理する。
- **サーバー空間検証:** 広げた`validPosition`の境界内チェックに加え、エリアID、地形高さ、壁/入口、最大速度、ジャンプと段差を検証。クライアントの申告座標だけを無条件に受け入れない。プレイヤー全員のworldSeedとroom座標系を一致させる。
- **イベントの例（設計案・現行APIには未実装）:**
  - `world_snapshot` → `{revision, worldSeed, signText, doorState, lightShow, mediaRef}`
  - `world_patch` → `{commandId, baseRevision, key, value}`
  - `world_ack` → `{commandId, revision}`
  - `combat_fire` → `{shotId, sequence, yaw, pitch, clientTick}`
  - `combat_result` → `{shotId, targetId, damage, hp, eliminated, respawnAt}`
  - `match_join`, `match_start`, `match_state`, `match_finish`
- リビジョン、ID重複排除、上限文字数、数値範囲、レート制限をサーバーで検査。共有状態は更新差分だけ普段送信し、入室時/再接続時にスナップショットを渡す。写真データをHP更新やライト切り替えのたびに全量再送しない。
- **ルームの管理権限:** 現状は招待URL所持者が写真を変更できる。編集者/閲覧者/ホストの権限設計と本人確認可能な権限トークンを導入する。ゲスト招待URLにホスト用の秘密鍵を混ぜない。アカウントなしの暫定運用なら、ホスト専用の別のランダムな編集キーを保護して扱う。権限検査は必ずサーバー側。
- **通信トラブル:** 再接続・再入室時は確定済みsnapshotを復元し、重複イベントや旧sessionを排除。接続が切れてもソロ探索を続けられる。マッチでは結果を確定するまで勝利表示しない。
- **屋内SAFE ZONE:** パーティールームと交流広場はPvP不可。アリーナに自発的に入場した人だけPvP可能。家庭向けポップなエネルギーブラスターとして実装、血・暴力的な損傷表現は不要。

### 5. Phase 4-A：THE DOOR + 屋外MVP — 最初のPR

**作るもの**
1. 旧`PartyWorld`を変更最小で保存し、屋内東側に開口を設置。扉は近づくと開く見た目で、開口から実際に出入りできる。
2. `OutdoorWorld`と`WorldManager`を新設。初期屋外は平らな地面・広場・池・木のグループ・ボクセル風岩、空/夜のフォグと街灯を作成。
3. 木・草・石・葦の繰り返し配置は`InstancedMesh`を原則とする。池の水面は低コストのシェーダーまたは半透明の平面。最初は遊泳不要、池の外周は衝突と救済経路を用意。
4. 16×16単位のチャンクを定義。カメラに近い3×3〜5×5程度をアクティブにし、離れた塊は描画・更新を抑制。地形のシードと座標がどの端末でも同じになるよう固定。
5. 衝突判定を屋内の水平AABBから**地面高さ＋障害物判定**へ拡張。初期は屋外地面y≈0、カメラ高さ1.65。将来の高低差に対応する`getGroundHeight(x,z)`と`canStepUp`を定義。
6. サーバー側の許可座標・進入エリア検証も合わせて変更する。屋外に出た後も別端末にアバターが表示される。
7. 戻ると写真・照明・看板は元のまま。1人モードでも全域探索可。

**Aの合格条件**
- 3台が同じルームに入れる。3人が扉を通って屋外に出て、戻れる。
- 障害物・壁のすり抜けがない。屋外移動がサーバーの不正座標検証で拒否されない。
- 屋内の既存操作、ジャンプ、写真共有に回帰不具合がない。
- 動画で「スタート→屋内→扉→池→屋内へ戻る」が連続して確認できる。

### 6. Phase 4-B：SHARED SIGN + 自分たちのワールド

**看板対象:** 現在のGAME ROOMロゴは屋内奥正面の `sign("GAME ROOM",...,0,2.5,-15.75,7.4,1.65,...)`。外観をいきなり消さず、上部ロゴと横流しニュース帯を分離する。既存のライトと看板周辺の設置物に干渉しない。

**動作**
- 近くで中央照準を合わせる→編集可能な場合は「看板を編集」。
- 日本語・英数字・絵文字に対応。上限80 Unicode文字を目安、改行・制御文字・HTMLを除去。外部URLのクリックリンク化はしない。
- 入力した文字が右→左へ途切れずスクロールする。CanvasTexture更新は最大15fpsなどに制限。スマホで読める文字サイズとコントラストを確保。
- テキストをサーバーが検証・保存・全員に配信。3人目や再入室でも同じ文字。
- オンライン時は権限付き編集。ソロでは端末内編集可能。

**Bの合格条件:** 1台で変更→他2台へ反映→全端末再読み込み後に復元。画像共有とライト共有はそのまま成功。過長文字や連打はサーバーが拒否。

### 7. Phase 4-C：AIM + HP + ENERGY BLASTER

**操作/UI**
- 中央の小さな点を常設Raycasterの基準とする。通常はニュートラル、的やインタラクト対象に合うと色とサイズをさりげなく変更。命中可能なオブジェクトに名前と操作距離を表示。
- iPhone右下に発射ボタン（既存JUMPと競合しない位置）、PCは左クリック/任意キー。左親指の移動、右親指の視点と発射の同時操作を設計。インタラクトUIは射撃と排他。
- 自分のHP=100、武器はポップなエネルギーブラスター。仮設定: 1命中20ダメージ、クールダウン350ms、最大射程35、アリーナのみ対人命中、リスポーン時2秒無敵。バランス値は設定ファイル化。
- フラッシュ、短い発光軌跡、ヒットマーカー、軽い効果音。描画/音はオプションで弱められる。画面を激しく揺らさない。
- 射撃はクライアント`Raycaster`で予測エフェクトをすぐ表示、**ダメージと勝敗はサーバーが決定**。`targetId`や命中結果をクライアントから受け取って無条件で採用しない。
- サーバーは許可エリア、発射者の生存、クールダウン、位置、視点、最大距離、標的の当たり判定を検証。必要に応じ少量の位置履歴から遅延補正。多数の弾丸メッシュをリアルタイム同期しない。
- HP0→脱落演出→スポーンに戻る。対人戦の同意がないプレイヤーやSAFE ZONEにダメージが及ばない。

**Cの合格条件:** 2台で同じ攻撃のHP変化と勝敗が一致。誤発射・連射・射程外・壁越し・不正IDを拒否。ジャンプ中の発射、被弾中の移動、再接続・リスポーンが破綻しない。

### 8. Phase 4-D：2つの完全に遊べるミニゲーム

**MINI GAMES端末: TARGET RUSH 30**
- 右奥筐体 `arcade(6.55,-13.6,"MINI GAMES",...)` から起動。近づき照準/「遊ぶ」で開始。
- 30秒間、移動する発光ターゲットをブラスターで撃つ。命中+10、コンボ最大×3、制限時間で終了。
- ソロ練習可能。オンラインはルーム内の参加者で同じタイマー・標的・スコアを共有。最終スコアはサーバー確定。
- リザルト（名前・点数・順位・再戦）を表示し、終了後は必ず屋内へ戻る。途中退出/通信断でも進行不能にならない。

**ARCADE端末: GLITCH SHIFT**
- 左奥筐体 `arcade(-6.55,-13.6,"ARCADE",...)` から起動。通常のパーティールームとは切り離した小型アリーナシーンへ入る。
- 床がブロック状に並ぶ空中ステージ。3〜5秒ごとに「安全な色」が告知され、ほかの色の床はフェードアウト。予告を必ず出す。
- 足場の落下/復帰・生存時間・順位をサーバーが判定。ソロでは練習モード。
- ランダムな見た目の演出はseedとサーバーのラウンド時刻に一致。フラッシュの連続点滅・強いカメラ回転は禁止、Reduced Motionを尊重する。
- 退出ボタン、再戦、タイムアウト、リスポーン、スコア、他プレイヤー観戦の導線を用意。

**Dの合格条件:** どちらも説明→開始→進行→終了→結果→再戦/退出まで完走。オンライン2〜3人でラウンド/順位が一致し、ソロでも遊べる。看板や写真共有に干渉しない。

### 9. Phase 4-E：3人で起こす「池の奇跡」オプション

- `Starlit Pond` に3つの発光結晶を置く。エイムでそれぞれを選択し、3人で同時に3秒ホールドすると空中に透明な光の橋が出現する。橋の出現はサーバーイベントで全員に反映。
- 単独プレイ用の順番スイッチ解放ルートを実装し、オンライン人数によってクリア不能にしない。
- 成功したら隠し島と記念のライトアップが短時間現れ、撮影に適した静かな演出が始まる。端末の低電力モードではパーティクルを減らす。
- 必須のA〜Dが完成した後の差別化機能。完成順を逆転させない。

### 10. iPhone最優先のパフォーマンス予算（目標・保証ではない）

- デバイス: iPhone Safari / iPad Safari / PC。iPhoneの縦・横を検証。
- FPS: 対象実機で30fps以上の安定を最低目標、60fpsは端末次第の努力目標。まず現行版のベースラインを同じ端末で測定する。
- フレーム予算: 60fps=16.7ms、30fps=33.3ms。各機能の追加前後でp50/p95のframe timeを計測。
- 初期性能仮目標: 可視draw calls≲150〜200、GPU負荷を増やす動的影は慎重に限定、フル解像度透明オブジェクトの多重重なりを避ける。これは現行の実測値ではない。
- 一度に表示するチャンクは距離に応じて制限、草はInstancedMesh、静的Meshのジオメトリを共有。草1本ごとに新しいMesh/Materialを生成しない。
- `renderer.setPixelRatio`の上限は現行の1.75を初期基準として維持し、必要に応じ端末性能を測って動的調整。勝手に超高解像度へ上げない。
- 遠くのアニメーション、ライト、粒子、音を停止/間引く。水面は高価な反射レンダリングよりシンプルなアニメーション/擬似反射を優先。
- ソロと3人接続の両方を記録。初期ロード、メモリ、draw calls、triangle数、WebSocket帯域を計測。
- 地形を何倍にもしたという理由だけでFPS改善を宣言しない。**実機で測定してから段階的に拡張する。**

### 11. セキュリティ、品質、アクセシビリティ

- 人の入力した看板テキストはDOMへ`innerHTML`で入れない。文字列長、制御文字、連打をサーバーで拒否する。
- エフェクト量・閃光・音量・振動はユーザーが低減/オフにできる。画面酔いを起こしやすい強制カメラ回転は行わない。
- 小型画面でJUMP・射撃・インタラクトが重ならない。ボタンは安全領域内、pointerIdの所有を維持。
- HPやスコアはサーバーが所有する。自称ダメージ・自称スコア・自称ホストは拒否。
- WebSocket messageの型、サイズ、速度、射撃頻度、対象ID、権限、roomId、タイムスタンプを確認。高頻度チャット・大量画像・無制限ルーム作成を許可しない。
- 家具、写真、戦闘、マッチの保存先と保持期間を分離。写真を共有しない選択肢を維持する。
- 世界のseed、チャンク境界、プレイヤー位置、シーン遷移のテストを複数端末で実行。古いクライアントと新サーバーのprotocol version互換を明示。
- 定期的にCloudflare利用量を確認。無料枠を超えそうな場合は通知・縮退方針を考える。重いゲーム結果を写真JPEGと一緒に大量ブロードキャストしない。

### 12. CI・テスト計画（必須）

1. **単体:** seed固定で地形一致、チャンク有効/無効、壁に開いたドア通過、地面高さ、射撃角度/距離、HP・無敵・復活、文字検証。
2. **Cloudflareローカル統合:** 3つのWebSocketで既存ルーム参加、屋内→屋外移動、看板変更、写真保持、照明、PvP判定、ミニゲーム得点と退出/再接続を検証。
3. **GitHub CI:** `npm run typecheck`、`npm test`、`npm run build`、`npm run check:worker` と機能別の統合テスト。全テスト完了前にmainへマージしない。
4. **実機:** iPhone A / iPad B / 別回線のiPhone C、縦/横画面、照明・モニター・扉・HP・2ゲームを確認。ローカルのヘッドレスブラウザ成功だけでSafari実機の動作を保証しない。
5. **障害:** WebSocket切断→再接続、途中入室、プレイヤー退出、ホスト離席、通信遅延、室内/屋外境界、リスポーン、ゲーム途中終了。
6. **回帰:** 元のURL、スタート画面、左右ジョイスティック、歩きながらジャンプ、写真を3人で共有、既存招待URL、ソロプレイをすべて維持。
7. **計測:** 変更前/変更後の同一端末で、初回ロード時間、10分間FPS p50/p95、メモリ、通信帯域を比較しREADMEに実測条件を残す。
